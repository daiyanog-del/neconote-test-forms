# neconote-test-forms

営業ツール「ネコノテアクション」のフォーム営業機能（ブックマークレットによる
フォーム自動入力＋人手送信の半自動フロー）を検証するための、架空会社のダミー静的サイトです。

純粋な静的 HTML/CSS/JS のみで構成されており、ビルドや外部ライブラリは不要です。
GitHub Pages でそのまま公開できます。

## 目的

- 会社概要ページやナビゲーションから「お問い合わせ」フォームを検出できるか
- 標準的なフォーム欄の自動入力ができるか
- 姓名分割・電話番号3分割・都道府県セレクトなど、入力が難しい形のフォームでも自動入力できるか
- 確認画面を挟む2段階フォーム（contact2.html）でも正しく動作するか
- 「営業お断り」文言があるページで、サーバー側の再チェックにより送信が停止扱いになるか

## 各ページの役割

| ファイル       | 役割                                                                 |
|----------------|----------------------------------------------------------------------|
| `index.html`   | 会社概要ページ。ナビと本文に「お問い合わせ」リンクあり               |
| `contact.html` | 標準的なお問い合わせフォーム（GET送信、thanks.htmlへ）              |
| `contact2.html`| 難しい形のフォーム（姓名分割・電話3分割・都道府県セレクト等）。確認画面を挟んでから送信する2段階フロー |
| `no-sales.html`| contact.htmlと同じフォームだが、営業お断り文言を明記したページ（再チェック停止の検証用） |
| `thanks.html`  | 送信完了ページ。URLクエリの内容を「受信内容」として一覧表示する（JSでURLSearchParamsを読み、textContentで描画） |
| `robots.txt`   | 全許可（User-agent: * / Allow: /）                                    |
| `style.css`    | 全ページ共通のシンプルなスタイル                                     |

## 注意: 「営業お断り」文言について

「営業お断り」「営業目的のお問い合わせはご遠慮ください」「セールスお断り」等の文言は、
**`no-sales.html` 以外の一切のページに書かないでください。**

ネコノテアクションのサーバー側再チェックはページ内のこうした文言を検出すると
送信を停止扱いにする仕組みになっているため、意図せず他ページに書いてしまうと
その挙動を正しく検証できなくなります。

## 受信サーバー（inbox）

`inbox/` フォルダは、`thanks.html` が送信した内容を記録するための簡易サーバー（FastAPI、Render の無料 Web サービスで稼働）です。GitHub Pages は静的サイトのため送信内容がどこにも残らず、確認画面での見た目確認しかできません。それを補うために、送信内容をサーバー側にも記録できるようにしています。

エンドポイント:

- `POST /submissions` — 送信内容（ページ・受信日時・入力項目）を1件記録する
- `GET /submissions` — 記録済みの内容を新しい順で一覧取得する
- `GET /health` — ヘルスチェック

注意点:

- Render の無料枠は一定時間アクセスがないと休眠するため、初回アクセス時は起動に最大1分ほどかかります。
- 記録内容はメモリ上に保存しているだけなので、サーバーが再起動すると消えます（Render のログには送信のたびに1行ずつ残ります）。

## GitHub Pages での公開手順（一言）

このフォルダの内容をリポジトリのルート（または `docs/` フォルダ）にそのまま置き、
GitHub のリポジトリ設定 → Pages で公開ブランチ・フォルダを指定するだけで公開できます。
ビルド手順は不要です。
